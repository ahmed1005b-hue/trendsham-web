# Spec: رمز تحقق QR على كل مستند PDF

**التاريخ**: 2026-11-12 · **الحالة**: معتمد (صاحب المشروع: "اختر الأفضل دائماً")

## الهدف

كل مستند PDF يصدره الموقع يحمل رمز QR ورمزاً قصيراً للكتابة اليدوية. من يمسحه يفتح صفحة على موقع تريندشام تؤكد أن المستند صادر منّا وتعرض بياناته الأصلية وحالته الحالية، فيُكشف أي تعديل أو تزوير. يحمي المنصة والعملاء والبائعين.

## المستندات المشمولة

| النوع | المصدر | صاحبه |
|---|---|---|
| `invoice` فاتورة طلب | `InvoiceController` (ويب + `/api/v1/orders/{id}/invoice`) | العميل صاحب الطلب |
| `seller_statement` كشف حساب بائع | `StatementService::generate` (ملف محفوظ) | البائع |
| `admin_report` التقرير المالي | `Admin\ReportController::exportPdf` | المدير الذي أصدره |

ملفات PDF التي يرفعها المستخدمون (هويات، إيصالات) خارج النطاق. المستندات المطبوعة قبل الميزة بلا رمز.

## القواعد

1. **الرمز**: 12 حرفاً عشوائياً من أبجدية بلا أحرف ملتبسة (`ABCDEFGHJKMNPQRSTUVWXYZ23456789`) ≈ 10^18 احتمال؛ يُعرض `TS-XXXX-XXXX-XXXX`. الرابط `/verify/{code}`. الكتابة اليدوية تقبل الأحرف الصغيرة والشرطات والمسافات.
2. **إعادة الاستعمال**: لكل مستند "بصمة بيانات" (sha256 لملخصه وتفاصيله). طباعة نفس المستند ببيانات لم تتغير ← نفس الرمز ونفس الملف المحفوظ. تغيّرت البيانات ← رمز جديد، والقديم يظهر "صدرت نسخة أحدث".
3. **بصمة الملف**: sha256 لبايتات PDF كما سُلّمت؛ يُحفظ الملف في `storage/app/private/documents/` (خارج git وغير عام).
4. **صفحة التحقق للزائر** (بلا دخول): صحيح/غير صحيح، النوع، الرقم، تاريخ الإصدار، المبلغ، الحالة الحالية. **بلا** اسم أو هاتف أو عنوان أو منتجات.
5. **صاحب المستند أو المدير** (مسجّل الدخول): يرى أيضاً التفاصيل (اسم العميل، المدينة، عدد القطع والمنتجات / اسم المتجر والأرصدة) ورابط الصفحة الأصلية إن وُجد.
6. **الحالات**:
   - `valid` — صحيح.
   - `order_cancelled` — فاتورة صحيحة لكن الطلب أُلغي بعد الإصدار.
   - `outdated` — صحيح لكن صدرت نسخة أحدث (بيانات الطلب تغيّرت / الكشف استُبدل).
   - رمز غير موجود ← "لا يوجد مستند بهذا الرمز — قد يكون مزوراً" (404 بنفس الصفحة).
7. **فحص الملف**: رفع PDF (حتى 10MB) ← مطابقة بصمته مع السجل: "مطابق تماماً للمستند الأصلي TS-…" أو "هذا الملف لا يطابق أي مستند أصلي — قد يكون معدَّلاً".
8. **الحماية**: `throttle:30,1` لصفحة الرمز و`throttle:10,1` لفحص الملف؛ لا تمييز في الرد يكشف وجود رموز قريبة.
9. لا يُسلَّم أي PDF برمز غير مسجّل: إن فشل التسجيل يفشل الطلب برسالة خطأ (رمز بلا سجل = مستند لا يمكن التحقق منه).

## التصميم

- جدول `issued_documents`: `code` (unique)، `type`، `subject_id`، `fingerprint` (فهرس مع type و subject_id)، `owner_user_id`، `issued_by`، `summary` json (عام)، `details` json (خاص)، `file_hash` (فهرس)، `file_path`، timestamps.
- `App\Documents\DocumentRegistry`:
  - `issue(type, subjectId, ownerId, summary, details, callable $render): IssuedPdf` — يجد المطابق (type+subject+fingerprint مع ملف موجود) فيعيده، وإلا يولّد رمزاً، يستدعي `$render($code)` لإنتاج الـ PDF بالرمز، يحسب البصمة، يحفظ الملف والسجل.
  - `register(type, subjectId, ownerId, summary, details, string $pdfBytes, string $code)` لكشف الحساب الذي له ملف خاص.
  - `newCode()`, `normalize(input)`, `status(IssuedDocument)`, `findByFile(bytes)`.
- `App\Documents\DocumentSnapshots`: ملخص/تفاصيل كل نوع (`invoice(Order)`, `statement(...)`, `report(...)`).
- Blade partial `pdf/_verify-stamp.blade.php` (QR عبر `<barcode type="QR">` من mPDF + `mpdf/qrcode`، الرمز القصير، الجملة) يُضمَّن في القوالب الثلاثة.
- `PdfService::render` يقبل `$data['verify']`؛ `StatementService::renderPdf` كذلك.
- `VerifyController`: `index` (حقل كتابة الرمز + رفع ملف)، `show(code)`، `checkFile`. صفحات ويب RTL بالوضعين.
- مساعد المحادثة: سؤال "كيف أتأكد أن الفاتورة أصلية؟".

## الاختبار

Feature: إصدار الفاتورة يُنشئ سجلاً ويضع الرمز في الـ PDF؛ طباعة ثانية بلا تغيير ← نفس الرمز والملف؛ تغيير الطلب ← رمز جديد والقديم `outdated`؛ إلغاء الطلب ← `order_cancelled`؛ الزائر لا يرى الاسم/الهاتف؛ صاحب الطلب والمدير يريان التفاصيل؛ عميل آخر يرى الملخص فقط؛ رمز غير موجود 404؛ إدخال يدوي بأحرف صغيرة وشرطات؛ فحص ملف أصلي ← مطابق، ملف معدَّل ← غير مطابق؛ كشف الحساب والتقرير يُسجَّلان؛ الكشف المستبدل ← `outdated`؛ التحديد بعدد المحاولات.
Unit: الرمز (الطول، الأبجدية، التطبيع).
