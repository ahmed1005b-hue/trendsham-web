# تصميم نظام الكوبونات (محفظة كوبونات)

التاريخ: 2026-11-11 · الحالة: معتمد من صاحب المشروع في المحادثة

## الهدف
نظام كوبونات بأسلوب تطبيقات التوصيل الكبرى: لا رموز يكتبها العميل، بل **محفظة كوبونات** لكل عميل،
والسلة تقترح أفضل كوبون. **من أنشأ الكوبون يتحمّل خصمه**.

## القرارات المعتمدة
| البند | القرار |
|---|---|
| التمويل | كوبون المدير ← من حصة المنصة (البائع يأخذ أرباحه كاملة). كوبون البائع ← من أرباح البائع (العمولة على السعر بعد الخصم) |
| الحصول | محفظة فقط، بلا رموز |
| توزيع كوبون المدير | العملاء الجدد / كل العملاء / عميل معيّن (يختار المدير كل مرة) |
| توزيع كوبون البائع | جمع من صفحة المتجر/المنتج + تلقائياً لمتابعي المتجر (الحاليين والجدد) |
| الكوبونات التلقائية | ترحيب عند التسجيل، "عُد إلينا"، شكر بعد التسليم، سلة متروكة (عيد الميلاد مؤجَّل؛ عمود birth_date موجود) |
| عدد الكوبونات في الطلب | واحد فقط؛ السلة تختار الأفضل والعميل يغيّره |
| الأنواع | نسبة % بحد أعلى، مبلغ ثابت، شحن مجاني، منتج هدية |
| النطاق | البائع: كل متجره أو منتجات محددة. المدير: كل الموقع أو أقسام أو متاجر |
| الشروط | حد أدنى للسلة، فترة صلاحية، حد لكل عميل، عدد إجمالي |

## البنية: وحدة جديدة (يُستبدل نظام الرموز القديم — لا توجد كوبونات في قاعدة البيانات)
1. **الحملة `coupon_campaigns`**: الممول (`funder`: platform|seller + `seller_profile_id`)، النوع
   (`percentage|fixed|free_shipping|gift`)، القيمة، الحد الأعلى للنسبة، الحد الأدنى للسلة، النطاق
   (`scope`: all|products|categories|stores + جدول `coupon_campaign_targets`)، الجمهور
   (`audience`: new_customers|all_customers|specific|collectable|followers|automatic + `trigger`)،
   الصلاحية (`starts_at`, `ends_at`, `valid_days` لنسخ المحفظة)، الحدود (`per_customer_limit`, `total_limit`,
   `issued_count`, `redeemed_count`)، منتج الهدية (`gift_product_id`, `gift_variant_id`, `buy_product_id`)، الحالة.
2. **محفظة العميل `customer_coupons`**: (`campaign_id`, `user_id`, `status`: available|reserved|used|expired|revoked,
   `expires_at`, `source`)، فريد على (campaign_id, user_id, sequence) لمنع التكرار.
3. **سجل الاستخدام `coupon_redemptions`**: (`customer_coupon_id`, `order_id`, `funder`, `seller_profile_id`,
   `discount_amount`, `shipping_discount`, `gift_cost`, `status`: applied|reversed).
4. **خدمات** (مصدر واحد للموقع والتطبيق):
   - `CouponEligibility` — هل الكوبون صالح لهذه السلة ولماذا لا (رسالة عربية دقيقة)، ومقدار التوفير.
   - `CouponSelector` — أفضل كوبون للسلة.
   - `CouponRedeemer` — تطبيق عند الدفع تحت قفل، وعكسه عند الإلغاء.
   - `CouponIssuer` — إصدار للمحافظ (فردي، جماعي على دفعات بالخلفية، متابعون، تلقائي) بلا تكرار.

## الحسابات المالية
مثال: منتج 100,000، عمولة 10%.
| الحالة | العميل | البائع | المنصة |
|---|---|---|---|
| بلا كوبون | 100,000 | 90,000 | 10,000 |
| كوبون المدير 20,000 | 80,000 | 90,000 | −10,000 |
| كوبون البائع 20,000 | 80,000 | 72,000 | 8,000 |

- `order_items.discount_amount` + عمود جديد `discount_funder` (platform|seller) لكل بند.
- **التسوية** (`OrderItem::settleCommission`): كوبون البائع ← الأساس = `subtotal − discount_amount`؛
  كوبون المنصة ← الأساس = `subtotal` كاملاً (المنصة تتحمل). قيد محاسبي "خصم كوبون" على الممول.
- **الشحن المجاني**: يُصفّر `orders.shipping_fee`، ويُسجَّل `shipping_discount` على الممول.
- **منتج الهدية**: بند طلب بسعر 0 وعلامة `is_gift`، يُخصم من مخزونه؛ تكلفته على الممول
  (كوبون منصة ← المنصة تدفع للبائع ثمن الهدية بسعرها).
- **الإلغاء**: عكس القيود، الكوبون يعود للمحفظة إن كان صالحاً، `redeemed_count` ينقص.

## تجربة العميل
- صفحة "كوبوناتي" (متاحة / مستخدمة / منتهية)، بطاقات بالقيمة والمصدر والشرط والعد التنازلي.
- صفحة المتجر/المنتج: شريط كوبونات مع زر "احفظ".
- السلة/الدفع: تطبيق أفضل كوبون تلقائياً + "تغيير" بقائمة الصالح (مع التوفير) وغير الصالح (مع السبب).
- إشعار عند وصول كوبون، وتذكير قبل الانتهاء بيوم.

## الإنشاء
- البائع: نموذج بخطوات (النوع، القيمة، النطاق، التوزيع، الشروط) + معاينة التكلفة + إحصائيات + إيقاف (لا حذف بعد الاستخدام).
- المدير: نفس النموذج + نطاق أقسام/متاجر + جمهور + تأكيد العدد قبل الإرسال الجماعي + إيقاف كوبونات البائعين.
- إعدادات الكوبونات التلقائية: تشغيل/إيقاف، القيمة، الأيام، منع التكرار.

## الحماية
- إعادة التحقق في الخادم عند الدفع؛ الكوبون يجب أن يكون في محفظة نفس العميل.
- قفل صف المحفظة والحملة أثناء الدفع؛ لا تجاوز للحدود مع التزامن.
- "العملاء الجدد" = لا طلبات سابقة **و** هاتف متحقَّق منه (`phone_verified_at`).
- الخصم ≤ قيمة المنتجات المشمولة؛ الإجمالي لا يصبح سالباً.
- متجر موقوف ← كوبوناته غير صالحة. لا تحويل للكوبونات بين العملاء.

## المراحل
1. **الأساس**: الجداول، الحسابات المالية والتسوية، المحفظة، السلة وأفضل كوبون، كوبونات المدير
   (جدد/الكل/عميل معيّن)، الأنواع: نسبة، مبلغ، شحن مجاني. إزالة نظام الرموز القديم. (موقع + تطبيق)
2. **كوبونات البائع**: إنشاء، جمع، متابعون، إحصائيات، منتج الهدية.
3. **التلقائية والتقارير**: الأربعة المعتمدة + تقارير التكلفة.

## الاختبار
اختبار قبل كل قاعدة (TDD): الأرباح في الحالات الثلاث والإلغاء، الحدود مع التكرار، الاستهداف،
اختيار الأفضل وأسباب عدم الصلاحية، الهدية والمخزون، عدم تكرار التلقائي. ثم فحص أمني بعد التنفيذ.
